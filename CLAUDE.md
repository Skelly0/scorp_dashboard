# SCORP Colony Player Dashboard — Frontend Companion

Static Svelte SPA + Python sync pipeline that surfaces a player-facing read of the `scorp_colony` GM workbook. Hosted on GitHub Pages, refreshed every 15 minutes via GitHub Action that pulls the Google Sheet's xlsx export.

## Architecture in one breath

GitHub Action → openpyxl → per-page JSON in `public/data/` → git commit → Pages rebuild → Svelte SPA fetches. Each successful sync also writes a per-year snapshot to `public/data/history/year-NNN.json` so the frontend can render historical sparklines on Status.

## Layout

- `scripts/` — Python sync (entry: `sync_sheet.py`; per-page extractors in `extractors/`; per-year snapshots in `history.py`)
- `src/` — Svelte SPA (one route per page, one store per page, shared components in `src/lib/components/`)
- `src/lib/components/` — Mission-Brutalist primitives: `Band`, `KpiBlock`, `Sparkline`, `OvertonRow`, `Bar`, `Tag`. Plus updated `StatTile`, `SituationCard`, `TierLadder`, `Heatmap`. Existing: `RadarChart`, `MoonBackdrop`, `MoonLoader`, `MapCanvas`, `LayerMenu`, `MadIndex`, `NavBar`, `SyncChip`, `ThemeToggle`. Catalog UI: `CatalogModal`, `ImprovementCard`. Route-specific composites: `WorkforceBand`, `ClassDetail`, `SubFactionPanel`.
- `src/lib/faction-colors.js` — class & GoI accent palettes (cosmetic only — used for 4px left-bar and faction-bar swatches)
- `src/lib/stores/history.js` — derived stores for treasury/stability/CF/population year-series
- `src/lib/stores/workforce.js` — derived from `$pops`; aggregates colony-wide demand/supply/fill, top-2 unemployed and short classes, mismatch flag
- `public/data/` — JSON output (managed by the Action; don't hand-edit). `history/index.json` lists available years; `history/year-NNN.json` is the per-year frozen snapshot.
- `tests/` — pytest, builds an in-memory fixture workbook (`tests/fixtures/build_test_workbook.py`)
- `tests-e2e/` — Playwright + axe a11y tests
- `.github/workflows/` — `sync.yml` (cron), `deploy-pages.yml` (build), `ci.yml` (PR tests)

## Critical conventions (NON-NEGOTIABLE)

1. **All sheet access via named ranges.** `wb.defined_names[name]` only — never `sheet["A24"]`. The backend reorganises rows; named ranges are the contract.
2. **Schema validator runs every sync.** When you add an extractor, register its required ranges in `BASE_REQUIRED_RANGES` (or `SENATE_REQUIRED_RANGES` for senate-only).
3. **`schema_version` bumps in lockstep.** Bump `SCHEMA_VERSION` in `sync_sheet.py` AND `EXPECTED_SCHEMA_VERSION` in `src/lib/stores/meta.js`. Mismatch = maintenance banner.
4. **Senate page is the privacy boundary.** When `Var_SenatePageVisible` is FALSE, the Action does NOT write `senate.json`. The frontend treats the absence of the file as "page does not exist."
5. **Atomic JSON writes.** Use `write_json_atomic` — write to `.tmp`, then rename. Never partial writes.
6. **Cache-bust JSON fetches.** Frontend fetches `meta.json?v=<random>` first; everything else uses `?v=${meta.synced_at}`. No mixed-version race.
7. **Numeric coercion.** All cell reads go through `coerce_number` — handles blanks, formula errors, and floats uniformly. Output: `float | None`. Frontend renders `None` as `—`.
8. **Blank-slot filtering.** Extensible blocks (15 class slots, 8 GoI slots, 15 party slots) reserve blanks for future growth. Always filter rows where col-A name is empty before serialising.
9. **Failure notifications are best-effort.** `notify_telegram.send` swallows its own exceptions — never let notification failure mask the real error.
10. **`Var_Year` is OPTIONAL but year-indexed history depends on it.** The named range points at `Colony!H1` in the live workbook and surfaces as `status.year` (int) in `status.json`. When present, sync writes/overwrites `public/data/history/year-NNN.json` (3-digit zero-padded) plus updates `public/data/history/index.json`. When absent, history is silently skipped — sync still succeeds. Year stays the same across many turns; we overwrite the same year file every sync until it ticks over.
11. **History writes are idempotent within a year, frozen across years.** While Var_Year holds, every sync overwrites the same `year-NNN.json` with the latest snapshot. When the year increments, the prior file stops being touched and effectively becomes archival. Don't expect turn-level granularity — the index axis is *year*.
12. **Design vocabulary is CSS classes in `global.css`, NOT Tailwind utilities.** `.band`, `.s-card`, `.s-card-pad`, `.s-card-header`, `.kpi-block` (+ `.critical` modifier — wrapper border treatment, + `.muted` modifier — softer border + dim `.kpi-label`; the `.kpi-num.muted` companion drops weight + colour for zero/inactive values), `.stat-tile`, `.bar-row`, `.bar` (+ `.crit`/`.good`/`.overflow` modifiers — `.overflow` is a diagonal-stripe overlay for ratios > 1.0), `.overton-row`, `.sit-card` (with `.sev-low`/`.sev-warn`/`.sev-crit` modifiers + `.sit-meter`/`.sit-meter-fill` severity bar), `.crisis-index` (with same `.sev-*` modifiers), `.s-card.critical` (mirrors `.kpi-block.critical`), `.tier`, `.heatmap`, `.tbl`, `.kv`, `.layer-tabs`, `.s-chip`, `.s-tag`, `.faction-bar`, `.spark`, `.cat-backdrop`, `.cat-modal`, `.cat-header`, `.cat-search`, `.cat-close`, `.cat-cat-strip`, `.cat-body`, `.cat-group`, `.cat-grid`, `.cat-card` (+ `.cat-card-title`/`.cat-card-row`/`.cat-card-notes`), `.cat-chip` (+ `.pos`/`.neg`/`.upkeep` modifiers), `.cat-empty`, `.inspector-empty-head`/`.inspector-empty-hints`/`.inspector-empty-key` (Map right-rail empty-state with keyboard hints). The `s-` prefix is used where the bare name might collide with Tailwind. Theme variables (`--bg-2`, `--accent-soft`, `--good`, `--crit-soft`, `--radar-overlay`, etc.) live on `:root[data-theme=…]`; *all three* themes must define every variable for cards to render correctly across themes.
13. **Shared extractor helpers live in `extractors/_common.py`.** Common scalar-reading/aggregation logic (`scalar_named`, `population_total`, `avg_satisfaction`, `net_delta_pct`) is centralised. When a second extractor needs the same logic, promote to `_common.py` rather than reaching into another extractor's `_`-prefixed private API.
14. **Schema validator splits hard vs soft requirements.** `BASE_REQUIRED_RANGES` are throw-on-missing (structural ranges every extractor needs). `SOFT_OPTIONAL_V3_RANGES` is documentation-only — those are read via `scalar_named()` (returns `None` for missing names) for scalars, or `read_named_range()` (returns `[]`) for per-class arrays. Either way the extractor naturally fills `None` per row and the frontend renders `—`, so the dashboard degrades gracefully if the GM hasn't named the range yet. `PopsimMobilityIn` / `PopsimMobilityOut` / `TotalBirths` follow this pattern; mirrors the `Var_Year` story.
15. **Map palettes are tier-loaded.** `palettes.terrain`, `palettes.resource`, `palettes.feature`, `palettes.improvement_category`, and `palettes.control` all use the same "named-range-then-fallback" pattern via `extractors/map.py:_palette()`. The frontend treats every palette key as optional — missing keys fall back to white or local control/faction colours. When you add a new typed overlay, follow this pattern; never throw on a missing palette.

## Common gotchas

1. **GitHub Pages CDN caches stable paths** (~10 min). Hashed Vite filenames solve JS/CSS but JSON is at stable paths — that's why we cache-bust on `meta.synced_at`. Don't remove the bust.
2. **`/export?format=xlsx` is undocumented.** Sometimes 429s. Sync script retries with backoff (5s/15s/45s). Three failures = exit non-zero = Telegram ping.
3. **GitHub cron drifts 5–15 min, occasionally skips.** That's why we surface the last-sync chip in nav. Don't promise an exact 15-minute cadence.
4. **Dark theme contrast.** Amber on near-black needs measurement to hit WCAG AA. The Playwright + axe job fails the build if it slips.
5. **Sub-faction range disagreement.** CLAUDE.md (backend) says rows 32-44; built workbook has it at U24:AC36. Trust the live Sheet over the docs. The extractor reads `SubFactionsBlock` named range — keep that pinned to wherever the live data actually lives.
6. **`partial_failures` in meta.json.** When an extractor crashes, sync continues without that page. Frontend reads `meta.partial_failures` and can show "this page failed to sync" — not implemented yet, just the data path is there.
7. **Svelte 4 `{@const}` placement.** `{@const}` must be the immediate child of `{#if}/{:else}/{#each}/<svelte:fragment>` etc — NOT inside an arbitrary HTML element. If you need a derived value inside a div, compute it via `$:` reactive in the script block.
8. **Tri-state theme system.** Three modes: `light` (Calm), `dark` (Cosmic), `schematic` (blueprint navy on cream). Adding/renaming one means touching FOUR places in lockstep: `THEMES` array in `src/lib/theme.js`, the `:root[data-theme=…]` block in `src/styles/global.css`, the pre-hydration validator in `index.html`, and the `THEMES` list in `tests-e2e/a11y.spec.js`. The toggle is a segmented pill (☀ ☾ ⊞), not a binary swap.
9. **`MoonLoader` is the canonical loading state; `MoonBackdrop` is the always-on ambient layer.** Both live in `src/lib/components/`. The loader is foreground (role="status", labelled, full opacity); the backdrop is fixed-position, viewport-responsive, low-opacity, `aria-hidden`, sits at `z-0` behind a `z-10` content wrapper in `App.svelte`. Both share the same canvas component — pass `decorative` to suppress ARIA + sr-only label and to honour `prefers-reduced-motion`. The texture (`src/lib/assets/moon-equirect.png`) is a Vite-bundled asset (NOT in `public/`) so it gets hashed and cache-busted with the rest of the build.
10. **Fixture/live workbook drift is handled narrowly.** `tests/fixtures/build_test_workbook.py` can lag behind live sheet layouts, so fix only the contract you are actively touching. `status.py` deliberately supports both legacy named ranges (`TreasuryMoney`, `TreasuryMoneyDelta`, `ResourceFlows`) and the live `Colony!B3` / `Colony!A8:F15` table so unit fixtures and the live workbook both pass. The live resource table columns are `Resource`, `Reserve`, `Income/turn`, `Improvements Upkeep`, `Upkeep/turn`, `Net/turn`; resource `upkeep` is the sum of the two upkeep columns and `delta` uses `Net/turn` when present. Don't use that as permission for broad cell-address reads elsewhere — named ranges remain the contract unless a field is explicitly documented as a live-layout fallback.
11. **History sparkline minimum.** `Sparkline.svelte` only renders the line+area when `data.length >= 2`. With one sample it shows "single sample"; with zero, "no history". Don't pass empty arrays expecting an empty SVG.
12. **`GITHUB_TOKEN`-authored pushes don't trigger downstream `push` workflows.** GitHub's anti-recursion safeguard. The scheduled Sync commits new JSON to `public/data/` using the default token, so the `Deploy to GitHub Pages` workflow's `push` trigger never fires from a sync commit — meaning data sits on `main` but isn't in the served `dist/`. Fix: `deploy-pages.yml` also has a `workflow_run` trigger chained to `Sync sheet → JSON` completion (gated by `conclusion == 'success'`). If you add another workflow that needs to react to sync commits, do the same — don't rely on `push`.
13. **Situations sheet layout: title row at 1, header row at 2, data starts row 3.** Unlike most extractors that use `min_row=2`, `extractors/situations.py` uses `min_row=3` because the live `Situations` sheet has a banner/title at row 1 *and* a "Name | Crisis Contribution | …" header at row 2. If you ever rebuild this extractor or add new sheets that share this convention, mirror the offset.
14. **Canvas 2D `fillStyle` does NOT resolve `var(--…)` custom properties** — neither standalone nor nested inside `color-mix()`. The assignment is silently ignored, leaving the previous valid fillStyle in place (or default black). Always pre-resolve theme tokens via `getComputedStyle(canvasOrRoot).getPropertyValue('--…').trim()` and substitute concrete strings before handing to canvas. `MoonLoader.svelte` and `MapCanvas.svelte` both do this. `MapCanvas` also accepts a `redrawKey` prop and `Map.svelte` threads `$theme` into it, so a theme flip triggers a redraw with freshly-resolved tokens. `MoonLoader` does NOT yet — if you flip themes during a long load, the loader colours stale until the next data/layer change. Default theme is `schematic` (set in `src/lib/theme.js` and `index.html`'s `data-theme` attribute).
15. **Filter ring colour priority is fixed.** When multiple filters are active on the Map, the ring uses the *resource → feature → improvement* priority (resource always wins). This is deterministic by design — multiple highlight colours per match would smear into noise. If you reorder priorities, update `MapCanvas.svelte:ringColor` AND the spec at `docs/superpowers/specs/2026-05-06-map-overlays-and-filtering-design.md` Section 6.2 in lockstep.
16. **Demographics band ordering.** `01 Pop Dynamics → 02 Class Vitals → (Class Detail · unnumbered, conditional on row click) → 03 Workforce → 04 Housing → 05 Food Security`. The detail band is rendered by `ClassDetail.svelte` between the Class Vitals table and the Workforce band, gated on a row-click selection state owned by `Demographics.svelte`. It is deliberately unnumbered (the `Band` component supports omitting `num`) so toggling a row never renumbers the three downstream bands. The Workforce band is rendered by `WorkforceBand.svelte` and is null-safe — it renders nothing when `$workforce` is null (i.e. before `pops.json` has loaded). Selection state is local to `Demographics.svelte` (no store); a reactive guard clears `selected` if the class disappears across a sync. The old standalone Population page is merged here: Demographics still loads `population.json` through `src/lib/stores/population.js`, adds Tier/Share to Class Vitals, and passes the selected population profile into `ClassDetail.svelte` for Population Profile, Class Pressure, and Worldview Chart cards. Keep `scripts/extractors/population.py`, `population.json`, and its store as backing data even though `/#/population` no longer exists. If you renumber, update both `Demographics.svelte` and the spec at `docs/superpowers/specs/2026-05-08-pops-into-demographics-design.md`.
17. **Open Graph card is hand-committed, animated, and URL-pinned.** `public/og-image.gif` is a 1200×630 animated GIF (the primary asset — Discord plays it, other platforms fall back to frame 1) and `public/og-image.png` is the static fallback (frame 0). Both are generated by `scripts/generate_og_image.py` (Pillow + numpy + Consolas, no JS toolchain needed). The script ports `MoonLoader.svelte`'s contour-wireframe moon — marching-squares contours + lat/lon graticule projected through a Y-axis-rotating orthographic transform — onto the top-right of the card, and reads the texture from `src/lib/assets/moon-equirect.png`. The GIF uses a 32-colour shared palette + `disposal=1` (overlay) so unchanged pixels don't re-encode; that's what keeps the file under 1 MB despite 30 frames. Currently pinned to the **schematic** palette (navy `#0e3a8a` on cream `#f4f1ea`) — to flip themes, swap the six colour tuples at the top of the script (and the moon `MOON_LINE*` / `MOON_DISK_FILL` / `MOON_LIMB` constants), re-run with both `--static` and the default GIF mode, commit both files. The `og:*` / `twitter:*` URLs in `index.html` are *absolute* and pinned to `https://skelly0.github.io/scorp_dashboard/` because Discord/social scrapers need fully-qualified URLs — Vite's `base: './'` only relativises script/css refs, not meta tags. The `theme-color` meta (Discord's left-edge bar) and the `og:image:alt` text both reflect the current palette — update those in lockstep when the image changes. If the repo is renamed or hosted elsewhere, update the URLs too.
18. **Sub-faction effective worldview is read directly from `SubFactionStances` on the `Sub-Factions` sheet — no per-class baseline math.** All inputs live on `Sub-Factions`: cols A-L for goal/influence/approval/etc. (surfaced via `SubFactionGoals` / `SubFactionGoal` / `SubFactionInfluences` / `SubFactionApprovals` / `SubFactionMinorGoals` / `SubFactionNationalShare`) and cols N-S for the per-sub-faction 6-axis stance (`SubFactionStances` → Expn / Auth / Corp / Tech / Faith / Mat). Every range is row-aligned at rows 6-17 (12 sub-factions; row 5 is the column header). `extractors/gois.py:_stance_row_to_worldview` maps each stance row to a `{axis: value | None}` dict; an empty/missing row yields `None` and the panel hides the radar. `SubFactionStances` is registered as soft-optional in the schema validator so an unfilled range degrades gracefully. The legacy `Sub-Faction Detail` mirror sheet, `SubFactionDetail` named range, and the earlier `PopsimWorldview` + `goal_delta` baseline computation are all retired. `GoITable` on the `Reference` sheet (the GM's hand-tuned mirror) remains in the live workbook for reference but the dashboard does not read it. Rename a sub-faction by editing `Sub-Factions` col B; everything downstream flows through.
19. **Map-page metric layers are tier-loaded.** `tile.upkeep`, `tile.workforce`, `tile.staffing` are all soft-fail per gotcha #14: missing `Staffing Efficiency` / live `Upkeep X` / live `Workforce <Class>` sheets hide their dropdown / inspect section. The extractor still reads the old dashed upkeep/workforce sheet names as compatibility fallbacks, but missing reports name the live contract (`Upkeep Energy`, `Workforce Engineers`, etc.). The frontend gates each dropdown on `map.available_categories.<category>` and derives grouped metric menu options from the emitted tile keys, so `helium3`/`money` upkeep tabs appear without hardcoding them as yield options. When you add a new metric category, mirror this pattern: register a flag, hide the dropdown when false, render `—` for missing per-tile values.
20. **Workforce sheet names follow `ClassTable`.** `extractors/map.py` reads class names from the `ClassTable` named range (the source of truth `pops.py` also uses), then attempts `Workforce <name>` first and `Workforce - <name>` second. There is no shared `CLASS_NAMES` constant; renaming a class in `ClassTable` flows through to both pages automatically. The frontend's `CLASS_COLORS` palette is independent and falls back to `var(--accent)` for unknown classes — heatmap colour for an unknown class is the resolved amber, not a hard error. Excel's 31-char sheet-name limit means class names ≥ 20 chars can produce truncated legacy sheet names that won't match `read_grid_optional` lookups; the test fixture pre-truncates one dashed legacy sheet to surface this realistically (see `tests/fixtures/build_test_workbook.py`).
21. **`LayerMenu` popup-menu component for grouped tabs.** `src/lib/components/LayerMenu.svelte` is the trigger-button-plus-floating-menu used by Map.svelte for the Yields / Upkeep / Workforce Demand dropdowns. Esc inside the popup `stopPropagation()`s — Map.svelte's page-level Esc handler (clear filters → un-pin) only fires when no popup is open. Outside-click closes via `<svelte:window on:click>`. The trigger label format is `{Label}` when inactive, `{Label} · {Sub-Label}` when this dropdown is the active layer; clicking the trigger when inactive dispatches the last-used sub without opening the popup (1-click toggle). When you add another grouped-options tab, reuse this component — don't reimplement.
22. **Map drawing coords are anchored at `BASE_TILE = 16`; rendered size is decoupled.** `MapCanvas.svelte` fits the full map at 100% by taking the smaller of available content width and available viewport content height, then applies the user-controlled zoom multiplier (`0.75×`–`2×`, default `1×`). The canvas always *draws* at BASE_TILE coordinates and applies `ctx.setTransform(displayScale * dpr, …)` once per draw to handle both scaling and Hi-DPI. The SVG `viewBox` likewise stays in BASE_TILE units, so all literal SVG coords (`width="10"`, `font-size="6"`, `r="2.5"`, etc.) keep working at any rendered size. Two-layer wrapper: `.map-canvas-wrap` measures available column width; `.map-viewport` holds focus + keyboard handlers, has `overflow:auto`, and gets an inline `--map-viewport-width` so the bordered scroll frame hugs the rendered map instead of leaving an empty side band; `.map-content` is sized inline to the rendered pixel dimensions. Border width matters: scale calculations subtract the 4px-left + 4px-right viewport border from available width/height, and `viewportCssW` adds that border back so mobile 100% does not create horizontal scroll. When you change the drawing pipeline, **never reach for the displayed pixel size from drawing code** — write at BASE_TILE coords and let the transform handle the rest. Zoom state lives in `Map.svelte` as a single source of truth, persisted to `localStorage['scorp.map.zoom']` via `src/lib/map-zoom.js` helpers (`clampZoom`/`stepZoom`/`resetZoom`/`readZoom`/`writeZoom` — all wrap localStorage in try/catch and clamp on read); `MapCanvas` is display-only and dispatches `zoomstep` events for the `+`/`-`/`0` keyboard shortcuts. The `.s-zoom` control sits inside `.layer-tabs` and includes the label, `−`/`+` buttons, a range slider, and reset/readout button. **The grid track hosting `<MapCanvas>` MUST use `minmax(0, 1fr)` — bare `1fr` is shorthand for `minmax(auto, 1fr)`, and the `auto` floor lets the column expand to the widest item's min-content. If the measured available width feeds back into content size, that creates a positive feedback loop: content grows → track grows → measured width grows → `fitScale` grows → content grows again. Each ResizeObserver tick multiplies by `zoom`, so a single click of `+` blows the map up by ~22× instead of 1.25× (verified in `tests-e2e/map-zoom.spec.js`'s "scales linearly" regression). Map.svelte uses `lg:grid-cols-[minmax(0,1fr)_300px]` precisely to break this loop. Tailwind's `grid-cols-1` already expands to `repeat(1, minmax(0, 1fr))` so single-column breakpoints are safe by default; arbitrary-value variants are the trap. If you add another grid breakpoint or move `<MapCanvas>` into a different track, keep the `minmax(0, …)` floor.**
23. **Improvement catalog is the canonical category source.** `src/lib/improvement-categories.js:getCategorySlug(name, catalog)` checks the catalog first via `resolveImprovementRow` (exact match → deterministic longest-shared-prefix fuzzy with min-length-4 floor and 75%-of-longer threshold), falls back to the legacy keyword regex (`regexCategorySlug`), then `'other'`. `extractors/catalog.py` accepts the live workbook shape where `ImprovementsCatalog` starts on the first data row and the headers sit one row above it; don't "fix" that back to header-only named ranges unless the live workbook changes. It also aliases live category labels into dashboard slugs: `Food → agri`, `Materials → materials`, `Housing → habitat`, `Faith/Culture/Recreation → civic`, `Research/Economy → science`. Map-canvas redraws are NOT triggered by `mapData` change alone for catalog arrivals — `MapCanvas.svelte` adds a reactive line that re-fires `drawTerrain(...)` when `$catalog` changes, so tiles re-colour when the catalog file lands after `map.json`. Catalog is loaded globally from `App.svelte` (NOT in Map's onMount) so the reactive trigger has a stable subscription window. In the Map inspector, `t.improvement.name` is the workbook's `Improvement Type`; `t.improvement.ownership_type` is the separate ownership classification and is often blank in live data. Don't move the load site or relabel those fields without updating that reasoning.
24. **Predicted Growth / Status Population delta are authoritative, not derived.** Demographics' Predicted Growth reads `totals.total_births - totals.total_deaths` from `demographics.json` — i.e. the GM workbook's `TotalBirths` named range minus `TotalDeathsPerTurn`. Status's Population KPI delta uses the same births-minus-deaths count via `status.demographics.total_births` / `total_deaths`, and the Status Pulse row surfaces `total_births` directly as "Births / year" beside "Deaths / year". Status's Pulse "Projected Growth" rate is also based on those actuals: `(total_births - total_deaths) / population_total * 100`; it must not display `net_delta_pct`, because the estimated rate can contradict the actual births/deaths totals. We did NOT keep the older `pop × (effective_growth × housing_growth_mult − cdr)` or `pop × net_delta_pct` rate-based estimates as fallbacks because the rate-based versions drift noticeably from per-class actuals (rate uses colony-wide satisfaction elasticity; housing mult only multiplies births; rounding only happens once at the end). When `TotalBirths` / `TotalDeathsPerTurn` / population are missing (or population is 0), the count/rate renders `—` rather than silently falling back to the worse number. The `effective_growth_rate` / `net_delta_pct` keys still flow through `extractors/demographics.py` and `extractors/status.py:_demographics_block` for historical/extractor compatibility, but frontend actual-growth displays should not use them.
25. **`housing.ratio` is derived from pop/capacity, not read from a named range.** The GM's `HousingRatio` cell in the workbook has historically drifted to 0 even when pop and capacity are both correct, which silently broke the Demographics "Pop / Capacity" bar (showed 0%). `extractors/demographics.py` now computes `ratio = pop / capacity` directly when capacity is non-zero, returning `None` for capacity 0/missing. The `HousingRatio` named range is removed from `BASE_REQUIRED_RANGES` and the test fixture; if you re-introduce a workbook source for this number, ensure pop and capacity remain the authoritative inputs (or rename the field to make the source explicit). This is the only field that violates "all sheet access via named ranges" — the derivation is intentional because pop/capacity already are named-range reads.
26. **Improvement glyphs render in every map mode; only the fill is mode-conditional.** `MapCanvas.svelte`'s SVG overlay always emits `cat.icon` (☀/⛏/◆/⌂/⌧/⚐/⚘/⚗/⌬) for tiles with improvements — the `tab === 'improvements'` switch only controls the inline `fill` attribute. In improvements mode the fill is the control-or-category palette colour: `tile.control` comes from the required `Control` map sheet, falls back to `improvement.owner` only for stale JSON, then falls back to category colour. The Control map mode is separate: it paints the canvas tile background by `tile.control ?? improvement.owner` using `palettes.control` first, then local control/GoI/class fallback colours, while glyphs stay outlined for legibility. The inspector labels this row `Control` under the Improvement section and does not render `Ownership Type`. In every other mode `fill={null}` is passed so Svelte omits the attribute and `.map-glyph--improvement` CSS takes over (`var(--bg)` fill + `var(--fg)` stroke), giving an outlined glyph that survives any heatmap underneath. Earlier behaviour rendered a generic `▣` placeholder outside improvements mode and lost the at-a-glance category read — don't reintroduce.
27. **Control map colours are canonical in frontend fallback code.** The major institutional controls are fixed as Administration `#38d39f` (green), Corporations `#ffd84d` (yellow), Unions `#ff5544` (red), and Research `#5ec3ff` (blue). `scripts/extractors/map.py:CONTROL_PALETTE` should emit those defaults for fresh syncs, but `MapCanvas.svelte` must resolve control colours through `src/lib/faction-colors.js:resolveControlColor()` so stale checked-in `map.json` palette values do not keep old colours alive. Preserve explicit workbook palette overrides except known legacy defaults.
28. **Tech effect chip colour is direction-of-good, not raw sign.** `TechCard.svelte:chipDirection()` maps `(type, sign of mag)` to chip class as: `yield +` → pos, `yield −` → neg, `workforce −` → pos (less labour needed = good for the player), `workforce +` → neg, `upkeep −` → pos, `upkeep +` → neg, `mag === 0` or unknown `type` → neutral. The extractor logs a stdout warning when an unknown type slug appears (see `extractors/tech.py:_log.warning`), so adding a new type later means inspecting the sync log, deciding the direction-of-good polarity, and extending both `_KNOWN_EFFECT_TYPES` in the extractor and the `chipDirection` map in lockstep. Changing this rule means updating both the spec at `docs/superpowers/specs/2026-05-09-tech-page-design.md` §5.2.2 and the chip-direction logic.
29. **Tech effect chips must be wide first, shrink-and-wrap safe second.** The Tech tree intentionally uses `repeat(auto-fit, minmax(min(100%, 520px), 1fr))` so branch columns are wide enough for effect chips to stay on one line at normal dashboard widths, while still collapsing to one phone-width column instead of forcing horizontal scroll. `.tech-card`, `.tech-grid-col`, `.tech-card-effects`, and `.tech-effect-chip` still need `min-width: 0`, and long chip/title/prereq/description text still needs `overflow-wrap: anywhere` as a last-resort containment rule. Without both pieces, long effect targets either overflow the bordered green positive chips or wrap too aggressively. Do not dim locked tech cards or prereq sub-labels with `opacity`: it lowers descendant text/chip contrast after token selection and makes axe fail; use concrete background/border/text tokens instead. `tests-e2e/tech.spec.js` mocks a populated `tech.json` with intentionally long effect targets because `public/data/tech.json` is optional and Vite preview may otherwise serve the SPA HTML fallback for the missing JSON path.
30. **Playwright must test a fresh preview by default.** `playwright.config.js` runs `npm run build && npm run preview -- --port 4173 --strictPort`, caps E2E at two workers, and only reuses an already-running server when `PLAYWRIGHT_REUSE_SERVER=1`. Reusing a stale Vite preview can make axe report old CSS tokens even after `dist/` is rebuilt; letting Vite auto-hop to another port while Playwright still targets `4173` has the same failure mode, so keep `--strictPort` too. On Windows, high worker fan-out can make the single preview server drop late in the run, producing connection-refused noise after otherwise-green specs.
31. **Missing optional JSON can look like HTML, not 404.** Vite preview's SPA fallback can serve `index.html` with a 200 for absent `public/data/<page>.json` files. `fetchPage()` treats `text/html` as `null` for the same reason it treats 404 as `null`; this keeps optional/data-conditional pages such as Tech on their empty-state path instead of throwing JSON parse errors.
32. **Vitest must ignore nested agent worktrees.** The main checkout can contain `.claude/worktrees/**` with stale copies of old branches. If Vitest's `test.exclude` is narrowed, keep `**/node_modules/**`, `.claude/worktrees/**`, and `.codex/worktrees/**` excluded or `npm run test -- run` will discover old tests and fail for reasons unrelated to the current branch.
33. **Tech "Active" means researched, not available.** `TechCard.svelte` shows an explicit `.tech-active-chip` in every card header: `Active` / `.on` only when `t.researched === true`; every available or locked-but-unresearched tech is `Inactive` / `.off`. Keep this separate from the existing badge (`✓` researched, `⚡` available-to-research, `🔒` locked) so the UI does not blur "effects are live" with "can be bought next." `tests-e2e/tech.spec.js` has a mocked populated tree that asserts one active researched card, inactive available cards, and an inactive locked card.
34. **Status headline ratio KPIs are percent-rendered and value-toned.** `Status.svelte` renders Stability, Crisis Factor, and Gov Approval through `src/lib/status-metrics.js:formatStatusPercent()` and `statusMetricTone()`, not inline `.toFixed(2)` decimals. The shared thresholds are `<0.33`, `<0.66`, otherwise high. For Stability and Gov Approval, low → `crit` (red), medium → `warn` (yellow), high → `good` (green). Crisis Factor passes `{ lowerIsBetter: true }`, so low → green and high → red. Demographics' Avg Satisfaction KPI also uses `statusMetricTone()` on `totals.avg_satisfaction` while keeping its decimal display, so low satisfaction is red, middle is orange, and high is green on the same 0..1 scale. `KpiBlock.svelte` accepts an explicit `tone` prop that also drives sparkline colour and `tone-*` border classes. If those thresholds, polarity rules, or colours change, update `src/lib/status-metrics.test.js`, `src/lib/components/KpiBlock.test.js`, demographics e2e coverage, and the `.kpi-block .kpi-num.warn` / `.kpi-block.tone-*` CSS in lockstep.
35. **Status headline economy KPI uses the Money resource, not `treasury`.** The old "Government Revenue" tile was misleading because `status.treasury.money` is the Colony sheet's all-resource total. `Status.svelte` now finds the `Money` row in `status.resources`, displays its `current` reserve as the headline `Money` KPI, and uses that row's gross `income`/`upkeep` chips plus `delta` for the footer. Keep `status.treasury` in JSON/history for archival compatibility unless you migrate `scripts/history.py`, `src/lib/stores/history.js`, fixtures, and history tests together, but do not put it back into the player-facing Status headline. Money is also filtered out of the Resource Flows tile grid below (case-insensitive name match on the `each` block) since it would otherwise show the same reserve + chips twice on the same screen.
36. **Map inspector yield values truncate, not round.** The Map tile detail box renders non-zero `tile.yields` via `MapInspector.svelte:formatYieldValue()`, which truncates toward zero at two decimal places and preserves the leading `+` for positive values. Do not replace this with `toFixed(2)` unless the gameplay meaning changes: `1.239` should display as `+1.23`, and `-2.987` as `-2.98`. `tests-e2e/map.spec.js` mocks a tiny `map.json` to lock this behavior down.
37. **Cropsim page reads named tables, not Cropsim cell addresses.** The live workbook now exposes `CropsimProductionTable` (`Cropsim!A4:C9`), `CropsimDemandTable` (`Cropsim!A12:D23`), and `CropsimAggregateTable` (`Cropsim!A25:B29`) alongside the existing scalar food names (`FoodSecurityRatio`, `FoodPerCap`, `FoodVarietyIndex`). `scripts/extractors/cropsim.py` serializes those blocks to `public/data/cropsim.json`; `src/routes/Cropsim.svelte` is the dedicated dashboard page at `/#/cropsim`. If the Cropsim sheet grows, extend those named ranges in the workbook first, then update the fixture and extractor tests. Do not introduce raw Cropsim cell reads to work around a stale named range.
38. **Mobile layout is shared-route, not mobile-route.** The dashboard stays on the same hash routes at phone widths. Route sections use `px-3 py-4 md:px-6 md:py-5`; touch upgrades live in `global.css` under `(hover: none) and (pointer: coarse)`; heatmaps and wide tables must scroll internally via `.heatmap-scroll` / `.tbl-scroll` so `document.documentElement.scrollWidth <= window.innerWidth + 1` remains true in `tests-e2e/mobile-flow.spec.js`. Map inspection is the one exception to inline desktop layout: `MapInspector.svelte` renders in the right rail at `md+` and inside `MapBottomSheet.svelte` below `md` when `pinnedTile` is set. Pinch zoom uses `scaleZoom` / `pinchMathStep` in `src/lib/map-zoom.js`; keyboard and button zoom still use stepped `stepZoom`.
39. **Status Resource Flows boxes show gross numeric chips only.** `Status.svelte` passes `resource.income` and `resource.upkeep` into `StatTile.details` so each resource tile shows two bare numbers (`+income`, `-upkeep`) under the reserve value. Do not add "Yield", "Income", or "Upkeep" text inside the boxes, and do not fall back from net-only `delta` to invented gross values. The tests in `src/routes/Status.test.js` cover all three cases, including `0 / 0` resources.
40. **GoIs page displays the workbook's `GOI VALUE CAPTURED POP` table.** `extractors/gois.py` reads the `GoIValueCapturedPop` named range for `gois.json.pop_capture_matrix.values`, and `GoIs.svelte` labels the heatmap with the exact workbook table title. The cells are grouped integer people-counts, not percentages. Keep `PopCaptureBase` required too: it still drives best-effort `main_class` inference for each GoI, but it is no longer the displayed heatmap source.
41. **Weekly hours worked stops before union capture.** The live workbook exposes `WeeklyHoursWorkedTable` on `GoI Modifiers!A57:C72` (Class, Baseline Hours/wk, Current Hours/wk). It is soft-optional in `validate_schema.py`; `extractors/pops.py` indexes it by class and emits only `workforce.weekly_hours_worked` into `pops.json`, and `ClassDetail.svelte` renders it as `Weekly Hours` inside the per-class Workforce card. Do not extend the named range or JSON to cols D:F; those are the hours-above-baseline / union-capture mechanics and are intentionally not surfaced on the player dashboard.
42. **Cropsim Food Reserve reuses Status resource semantics.** `Cropsim.svelte` loads `status.json` alongside `cropsim.json` so the Food Balance KPI row can show `Food Reserve` from the Status Food resource's `current` stockpile. Its foot chips mirror Status Resource Flows: bare `+income` and `-upkeep` numbers, using Cropsim total supply/demand only as a display fallback while Status is still loading. The Cropsim supply-minus-demand KPI is labelled `Net/Turn`; do not relabel it back to `Balance` or split Supply/Demand into separate top-row KPI tiles unless the page layout is intentionally redesigned. `KpiBlock.svelte` supports `details` for this shared bare-chip pattern.
43. **Tech accrued RP is a named scalar, not derived from researched costs.** The workbook exposes `AccruedResearchPoints` on `Tech & Institutions!G1`, beside the visible `Accrued Research Points:` label. `scripts/extractors/tech.py` reads it as soft-optional and emits `tech.json.research_points.accrued`; missing or formula-error values render as `—`. `Tech.svelte` still derives `RP Committed` from researched tech costs, and the `RP Accrued` KPI's remaining chip is `accrued - committed`. Do not replace accrued RP with a sum of researched costs — those are different game concepts.
44. **Parties has both compatibility proxy and captured-support data.** `parties.json.class_compat_matrix.values` remains the workbook's 0..1 compatibility score; the frontend only converts it to fallback `Party Pops` counts through `src/lib/party-compat.js:classCompatPopMatrix()`. The richer `party_capture_pct_matrix` and `party_capture_pop_matrix` come from the `Party and GoI Pop Capture` sheet's `PARTY VALUE CAPTURE %` and `PARTY VALUE CAPTURED POP` blocks, located by title/header rather than named ranges. `Parties.svelte` uses summed captured pop as the visible `Supporters` count and the top-class list source. Keep these concepts separate: compatibility is a proxy, captured support is the workbook's exclusive class x party split. `Heatmap.svelte` supports `format="int"` and `format="pctSign"` for these tables. The two class×party heatmaps (`% of Class` and `Supporters`) share a single tabbed card driven by `supportTab` state (default `pop` — `Supporters` is authoritative); GoI Compatibility stays on its own band because its axes are party×GoI, not class×party. The tab strip reuses `.layer-tabs` markup, so a restyle of the Map's layer tabs also restyles this card.
45. **Parties intentionally omit per-party closest GoI.** The workbook still contains a closest-GoI column and party x GoI compatibility values, but `scripts/extractors/parties.py` must not emit a `closest_goi` field for party records, and `Parties.svelte` must not render a closest-GoI label or colour party cards from it. The separate GoI compatibility matrix can stay because it is an explicit cross-table, not a per-party identity badge.
46. **MAD Index is displayed as Overton distance.** The workbook field remains `mad_index`, but the player-facing dashboard labels it through `src/lib/components/MadIndex.svelte` as "Overton distance" with `MAD Index` as the alias/tooltip. Negative values are inside or closer to the current Overton center; positive values move toward/outside the edge. `Parties.svelte` uses the full helper text, while `GoIs.svelte` uses the compact variant so the KPI grid stays tight. If the workbook formula or thresholds change, update `MadIndex.svelte` labels/classification and verify both Parties and GoIs layouts.
47. **Favicon follows the schematic brand mark.** `public/favicon.svg` is hand-authored as a compact cream/navy (`#f4f1ea` / `#0e3a8a`) blueprint-grid wireframe moon. Keep it visually aligned with the schematic OG card and `MoonLoader` mood; if the schematic palette changes, update this favicon alongside `index.html`'s `theme-color`, `public/og-image.*`, and the OG alt text.
48. **Radar stance labels are full words.** `RadarChart.svelte` renders the high-pole stance labels from `AXIS_HIGH_LABELS` verbatim on every radar chart; do not reintroduce `slice(0, 4)`-style abbreviations. The component side-anchors labels near the left/right SVG edges so the full words remain decipherable in compact party cards as well as larger GoI, class detail, and sub-faction charts. `src/lib/components/RadarChart.test.js` locks this down.
49. **KPI/StatTile font clamps MUST stay gated to coarse-pointer media.** `.kpi-block .kpi-num` and `.stat-tile .val` use `font-size: clamp(...)` + `overflow-wrap: anywhere` to stay readable at phone widths; both rules live inside `@media (hover: none) and (pointer: coarse)` in `src/styles/global.css` for that reason. If you move/duplicate those overrides outside the media query, desktop KPIs sitting in 2/12 grid columns (Status Population at `92,000`, Demographics `Predicted Growth` at `+241 / year`, Tech's 5-up KPI row once any value crosses 4 digits) will wrap mid-digit — `overflow-wrap: anywhere` allows unbreakable numeric strings to snap to a new line on character boundaries. The original mobile-friendliness pass landed these rules outside the gate and the regression shipped; do not reintroduce that shape.

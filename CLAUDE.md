# SCORP Colony Player Dashboard — Frontend Companion

Static Svelte SPA + Python sync pipeline that surfaces a player-facing read of the `scorp_colony` GM workbook. Hosted on GitHub Pages, refreshed every 15 minutes via GitHub Action that pulls the Google Sheet's xlsx export.

## Architecture in one breath

GitHub Action → openpyxl → per-page JSON in `public/data/` → git commit → Pages rebuild → Svelte SPA fetches. Each successful sync also writes a per-year snapshot to `public/data/history/year-NNN.json` so the frontend can render historical sparklines on Status.

Existing: `RadarChart`, `MoonBackdrop`, `MoonLoader`, `MapCanvas`, `LayerMenu`, `MadIndex`, `NavBar`, `SyncChip`, `ThemeToggle`. Catalog UI: `CatalogModal`, `ImprovementCard`. Route-specific composites: `WorkforceBand`, `ClassDetail`, `SubFactionPanel`, `SeatChamber` (the last retired from the live Congress page but kept as a component). Parties surface: `parties/*` (`RosterView`, `AllegianceWeb`, `SpectrumView`, `SupportView`, plus SVG primitives `VoteShareBar`, `SupportSankey`, `SpectrumScatter`). Congress surface: `congress/*` (`ChamberView`, `FederationsView`, `PartyHemicycle`, `FederationMatrix`); `FederationChamber` is kept as a component but no longer rendered on the page. Shared `ReadoutStrip` (the mockup's at-a-glance stat bar, on both pages). Shared helpers `src/lib/congress-power.js` (Banzhaf power / majority quota / ENP, pure+tested), `src/lib/contrast.js` (luminance→ink), `src/lib/short-name.js` (party acronyms). Command surface: `command/*` (`CommandView`, `VitalSigns`, `VitalTile`, `ResourceTelemetry`, `OvertonTrack`, `OvertonWindow`, `SituationBoard`) + `telemetry/*` (`TelemetryView`, `TrendChart`, `RingGauge`, `Instruments`, `ResourceSparklines`, `SituationReadout`), plus shared `MiniBar`, `Swatch`, `TimelineBar`, `ScanlineOverlay`.
- `src/lib/faction-colors.js` — class & GoI accent palettes (cosmetic only — used for 4px left-bar and faction-bar swatches)
- `src/lib/stores/history.js` — derived stores for treasury/stability/CF/population year-series
- `src/lib/stores/timeline.js` — Command page per-year frame assembly (live year = `status.json`, archive years = history snapshots) + year cursor; pure builder in `src/lib/timeline-frames.js`, resource palette in `src/lib/resource-colors.js`

- `tests-e2e/` — Playwright + axe a11y tests
- `.github/workflows/` — `sync.yml` (cron), `deploy-pages.yml` (build), `ci.yml` (PR tests)

## Critical conventions (NON-NEGOTIABLE)

1. **All sheet access via named ranges.** `wb.defined_names[name]` only — never `sheet["A24"]`. The backend reorganises rows; named ranges are the contract.
2. **Schema validator runs every sync.** When you add an extractor, register its required ranges in `BASE_REQUIRED_RANGES` (or `SENATE_REQUIRED_RANGES` for senate-only).
3. **`schema_version` bumps in lockstep.** Bump `SCHEMA_VERSION` in `sync_sheet.py` AND `EXPECTED_SCHEMA_VERSION` in `src/lib/stores/meta.js`. Mismatch = maintenance banner.
4. **Senate page is the privacy boundary.** When `Var_SenatePageVisible` is FALSE, the Action does NOT write `senate.json`. The frontend treats the absence of the file as "page does not exist."
5. **Atomic JSON writes.** Use `write_json_atomic` — write to `.tmp`, then rename. Never partial writes.
6. **Cache-bust JSON fetches.** Frontend fetches `meta.json?v=<random>` first; everything else uses `?v=${meta.synced_at}`. No mixed-version race.
7. **Numeric coercion.** All cell reads go through `coerce_number` — handles blanks, formula errors, and floats uniformly. Output: `float | None`. Frontend renders `None` as `—`.
8. **Blank-slot filtering.** Extensible blocks (15 class slots, 8 GoI slots currently holding 5 live GoIs + 3 blanks, 15 party slots) reserve blanks for future growth. Always filter rows where col-A name is empty before serialising.
9. **Failure notifications are best-effort.** `notify_telegram.send` swallows its own exceptions — never let notification failure mask the real error.
10. **`Var_Year` is OPTIONAL but year-indexed history depends on it.** The named range points at `Colony!H1` in the live workbook and surfaces as `status.year` (int) in `status.json`. When present, sync writes/overwrites `public/data/history/year-NNN.json` (3-digit zero-padded) plus updates `public/data/history/index.json`. When absent, history is silently skipped — sync still succeeds. Year stays the same across many turns; we overwrite the same year file every sync until it ticks over.
11. **History writes are idempotent within a year, frozen across years.** While Var_Year holds, every sync overwrites the same `year-NNN.json` with the latest snapshot. When the year increments, the prior file stops being touched and effectively becomes archival. Don't expect turn-level granularity — the index axis is *year*.
12. **Design vocabulary is CSS classes in `global.css`, NOT Tailwind utilities.** `.band`, `.s-card`, `.s-card-pad`, `.s-card-header`, `.kpi-block` (+ `.critical` modifier — wrapper border treatment, + `.muted` modifier — softer border + dim `.kpi-label`; the `.kpi-num.muted` companion drops weight + colour for zero/inactive values), `.stat-tile`, `.bar-row`, `.bar` (+ `.crit`/`.good`/`.overflow` modifiers — `.overflow` is a diagonal-stripe overlay for ratios > 1.0), `.overton-row`, `.sit-card` (with `.sev-low`/`.sev-warn`/`.sev-crit` modifiers + `.sit-meter`/`.sit-meter-fill` severity bar), `.crisis-index` (with same `.sev-*` modifiers), `.s-card.critical` (mirrors `.kpi-block.critical`), `.tier`, `.heatmap`, `.tbl`, `.kv`, `.layer-tabs`, `.s-chip`, `.s-tag`, `.faction-bar`, `.spark`, `.cat-backdrop`, `.cat-modal`, `.cat-header`, `.cat-search`, `.cat-close`, `.cat-cat-strip`, `.cat-body`, `.cat-group`, `.cat-grid`, `.cat-card` (+ `.cat-card-title`/`.cat-card-row`/`.cat-card-notes`), `.cat-chip` (+ `.pos`/`.neg`/`.upkeep` modifiers), `.cat-empty`, `.inspector-empty-head`/`.inspector-empty-hints`/`.inspector-empty-key` (empty-state with keyboard hints — Map right rail and the GoIs sub-faction rail), `.stale-banner` (PageState partial-sync warning strip), `.skip-link` (App-level skip-to-content, visible on focus), `.kpi-row-secondary` (caps secondary KPI rows at 42px so they don't out-shout headline KPIs), `.seat-strip` / `.seat-rows` / `.seat-row` (Congress seat composition — the strip omits zero-seat parties; `.muted` rows keep them listed; `.seat-row-bar` is the per-party proportional meter shown at md+ only, where fixed name/count columns keep every row's meter on a shared scale). The `s-` prefix is used where the bare name might collide with Tailwind. Theme variables (`--bg-2`, `--accent-soft`, `--good`, `--crit-soft`, `--radar-overlay`, etc.) live on `:root[data-theme=…]`; *all three* themes must define every variable for cards to render correctly across themes.
13. **Shared extractor helpers live in `extractors/_common.py`.** Common scalar-reading/aggregation logic (`scalar_named`, `population_total`, `avg_satisfaction`, `net_delta_pct`) is centralised. When a second extractor needs the same logic, promote to `_common.py` rather than reaching into another extractor's `_`-prefixed private API.
14. **Schema validator splits hard vs soft requirements.** `BASE_REQUIRED_RANGES` are throw-on-missing (structural ranges every extractor needs). `SOFT_OPTIONAL_V3_RANGES` is documentation-only — those are read via `scalar_named()` (returns `None` for missing names) for scalars, or `read_named_range()` (returns `[]`) for per-class arrays. Either way the extractor naturally fills `None` per row and the frontend renders `—`, so the dashboard degrades gracefully if the GM hasn't named the range yet. `PopsimMobilityIn` / `PopsimMobilityOut` / `TotalBirths` follow this pattern; mirrors the `Var_Year` story.
15. **Map palettes are tier-loaded.** `palettes.terrain`, `palettes.resource`, `palettes.feature`, `palettes.improvement_category`, and `palettes.control` all use the same "named-range-then-fallback" pattern via `extractors/map.py:_palette()`. The frontend treats every palette key as optional — missing keys fall back to white or local control/faction colours. When you add a new typed overlay, follow this pattern; never throw on a missing palette.

## Common gotchas

1. **GitHub Pages CDN caches stable paths** (~10 min). Hashed Vite filenames solve JS/CSS but JSON is at stable paths — that's why we cache-bust on `meta.synced_at`. Don't remove the bust.
2. **`/export?format=xlsx` is undocumented.** Sometimes 429s. Sync script retries with backoff (5s/15s/45s). Three failures = exit non-zero = Telegram ping.
3. **GitHub cron drifts 5–15 min, occasionally skips.** That's why we surface the last-sync chip in nav. Don't promise an exact 15-minute cadence.
4. **Dark theme contrast.** Amber on near-black needs measurement to hit WCAG AA. The Playwright + axe job fails the build if it slips.
5. **Sub-faction range disagreement.** CLAUDE.md (backend) says rows 32-44; built workbook has it at U24:AC36. Trust the live Sheet over the docs. The extractor reads `SubFactionsBlock` named range — keep that pinned to wherever the live data actually lives.
6. **`partial_failures` in meta.json.** When an extractor crashes, sync continues without that page and records the page key. The frontend surfaces it: `PageState.svelte` renders a warn-toned `.stale-banner` ("this page failed to sync — showing data from the last successful update") on affected routes, and `SyncChip` switches to a warn state (⚠ prefix, failed pages in the title); the stale-sync crit state (> 3h) outranks it. Page keys match the extractor registry in `sync_sheet.py` plus `senate`; multi-source routes pass arrays (Demographics `['demographics','pops','population']`, Cropsim `['cropsim','status']`, Parties `['parties','pops']`).
7. **Svelte 4 `{@const}` placement.** `{@const}` must be the immediate child of `{#if}/{:else}/{#each}/<svelte:fragment>` etc — NOT inside an arbitrary HTML element. If you need a derived value inside a div, compute it via `$:` reactive in the script block.
8. **Tri-state theme system.** Three modes: `light` (Calm), `dark` (Cosmic), `schematic` (blueprint navy on cream). Adding/renaming one means touching FOUR places in lockstep: `THEMES` array in `src/lib/theme.js`, the `:root[data-theme=…]` block in `src/styles/global.css`, the pre-hydration validator in `index.html`, and the `THEMES` list in `tests-e2e/a11y.spec.js`. The toggle is a segmented pill (☀ ☾ ⊞), not a binary swap.
9. **`MoonLoader` is the canonical loading state; `MoonBackdrop` is the always-on ambient layer.** Both live in `src/lib/components/`. The loader is foreground (role="status", labelled, full opacity); the backdrop is fixed-position, viewport-responsive, low-opacity, `aria-hidden`, sits at `z-0` behind a `z-10` content wrapper in `App.svelte`. Both share the same canvas component — pass `decorative` to suppress ARIA + sr-only label and to honour `prefers-reduced-motion`. The texture (`src/lib/assets/moon-equirect.png`) is a Vite-bundled asset (NOT in `public/`) so it gets hashed and cache-busted with the rest of the build.
10. **Fixture/live workbook drift is handled narrowly.** `tests/fixtures/build_test_workbook.py` can lag behind live sheet layouts, so fix only the contract you are actively touching. `status.py` deliberately supports both legacy named ranges (`TreasuryMoney`, `TreasuryMoneyDelta`, `ResourceFlows`) and the live `Colony!B3` / `Colony!A8:F15` table so unit fixtures and the live workbook both pass. The live resource table columns are `Resource`, `Reserve`, `Income/turn`, `Improvements Upkeep`, `Upkeep/turn`, `Net/turn`; resource `upkeep` is the sum of the two upkeep columns and `delta` uses `Net/turn` when present. Don't use that as permission for broad cell-address reads elsewhere — named ranges remain the contract unless a field is explicitly documented as a live-layout fallback.
11. **History sparkline minimum.** `Sparkline.svelte` only renders the line+area when `data.length >= 2`. With one sample it shows "single sample"; with zero, "no history". Don't pass empty arrays expecting an empty SVG.
12. **`GITHUB_TOKEN`-authored pushes don't trigger downstream `push` workflows.** GitHub's anti-recursion safeguard. The scheduled Sync commits new JSON to `public/data/` using the default token, so the `Deploy to GitHub Pages` workflow's `push` trigger never fires from a sync commit — meaning data sits on `main` but isn't in the served `dist/`. Fix: `deploy-pages.yml` also has a `workflow_run` trigger chained to `Sync sheet → JSON` completion (gated by `conclusion == 'success'`). If you add another workflow that needs to react to sync commits, do the same — don't rely on `push`.
13. **Situations sheet layout: title row at 1, header row at 2, data starts row 3.** Unlike most extractors that use `min_row=2`, `extractors/situations.py` uses `min_row=3` because the live `Situations` sheet has a banner/title at row 1 *and* a "Name | Crisis Contribution | …" header at row 2. If you ever rebuild this extractor or add new sheets that share this convention, mirror the offset.
14. **Canvas 2D `fillStyle` does NOT resolve `var(--…)` custom properties** — neither standalone nor nested inside `color-mix()`. The assignment is silently ignored, leaving the previous valid fillStyle in place (or default black). Always pre-resolve theme tokens via `getComputedStyle(canvasOrRoot).getPropertyValue('--…').trim()` and substitute concrete strings before handing to canvas. `MoonLoader.svelte` and `MapCanvas.svelte` both do this. `MapCanvas` also accepts a `redrawKey` prop and `Map.svelte` threads `$theme` into it, so a theme flip triggers a redraw with freshly-resolved tokens. `MoonLoader` also redraws on theme flips via its reactive `currentTheme` guard, so both canvases stay theme-correct. Default theme is `schematic` (set in `src/lib/theme.js` and `index.html`'s `data-theme` attribute).
15. **Filter ring colour priority is fixed.** When multiple filters are active on the Map, the ring uses the *resource → feature → improvement* priority (resource always wins). This is deterministic by design — multiple highlight colours per match would smear into noise. If you reorder priorities, update `MapCanvas.svelte:ringColor` AND the spec at `docs/superpowers/specs/2026-05-06-map-overlays-and-filtering-design.md` Section 6.2 in lockstep.
16. **Demographics band ordering.** `01 Pop Dynamics → 02 Class Vitals → (Class Detail · unnumbered, conditional on row click) → 03 Workforce → 04 Housing → 05 Food Security`. The detail band is rendered by `ClassDetail.svelte` between the Class Vitals table and the Workforce band, gated on a row-click selection state owned by `Demographics.svelte`. It is deliberately unnumbered (the `Band` component supports omitting `num`) so toggling a row never renumbers the three downstream bands. The Workforce band is rendered by `WorkforceBand.svelte` and is null-safe — it renders nothing when `$workforce` is null (i.e. before `pops.json` has loaded). Selection state is local to `Demographics.svelte` (no store); a reactive guard clears `selected` if the class disappears across a sync. The old standalone Population page is merged here: Demographics still loads `population.json` through `src/lib/stores/population.js`, adds Tier/Share to Class Vitals, and passes the selected population profile into `ClassDetail.svelte` for Population Profile, Class Pressure, and Worldview Chart cards. Keep `scripts/extractors/population.py`, `population.json`, and its store as backing data even though `/#/population` no longer exists. If you renumber, update both `Demographics.svelte` and the spec at `docs/superpowers/specs/2026-05-08-pops-into-demographics-design.md`.
17. **Open Graph card is hand-committed, animated, and URL-pinned.** `public/og-image.gif` is a 1200×630 animated GIF (the primary asset — Discord plays it, other platforms fall back to frame 1) and `public/og-image.png` is the static fallback (frame 0). Both are generated by `scripts/generate_og_image.py` (Pillow + numpy + Consolas, no JS toolchain needed). The script ports `MoonLoader.svelte`'s contour-wireframe moon — marching-squares contours + lat/lon graticule projected through a Y-axis-rotating orthographic transform — onto the top-right of the card, and reads the texture from `src/lib/assets/moon-equirect.png`. The GIF uses a 32-colour shared palette + `disposal=1` (overlay) so unchanged pixels don't re-encode; that's what keeps the file under 1 MB despite 30 frames. Currently pinned to the **schematic** palette (navy `#0e3a8a` on cream `#f4f1ea`) — to flip themes, swap the six colour tuples at the top of the script (and the moon `MOON_LINE*` / `MOON_DISK_FILL` / `MOON_LIMB` constants), re-run with both `--static` and the default GIF mode, commit both files. The `og:*` / `twitter:*` URLs in `index.html` are *absolute* and pinned to `https://skelly0.github.io/scorp_dashboard/` because Discord/social scrapers need fully-qualified URLs — Vite's `base: './'` only relativises script/css refs, not meta tags. The `theme-color` meta (Discord's left-edge bar) and the `og:image:alt` text both reflect the current palette — update those in lockstep when the image changes. If the repo is renamed or hosted elsewhere, update the URLs too.
18. **Sub-faction effective worldview is read directly from `SubFactionStances` on the `Sub-Factions` sheet — no per-class baseline math.** All inputs live on `Sub-Factions`: cols A-L for goal/influence/approval/etc. (surfaced via `SubFactionGoals` / `SubFactionGoal` / `SubFactionInfluences` / `SubFactionApprovals` / `SubFactionMinorGoals` / `SubFactionNationalShare`) and cols N-S for the per-sub-faction 6-axis stance (`SubFactionStances` → Expn / Auth / Corp / Tech / Faith / Mat). Every range is row-aligned at rows 6-20 (15 sub-factions; row 5 is the column header). `extractors/gois.py:_stance_row_to_worldview` maps each stance row to a `{axis: value | None}` dict; an empty/missing row yields `None` and the panel hides the radar. `SubFactionStances` is registered as soft-optional in the schema validator so an unfilled range degrades gracefully. The legacy `Sub-Faction Detail` mirror sheet, `SubFactionDetail` named range, and the earlier `PopsimWorldview` + `goal_delta` baseline computation are all retired. `GoITable` on the `Reference` sheet (the GM's hand-tuned mirror) remains in the live workbook for reference but the dashboard does not read it. Rename a sub-faction by editing `Sub-Factions` col B; everything downstream flows through.
19. **Map-page metric layers are tier-loaded.** `tile.upkeep`, `tile.workforce`, `tile.staffing` are all soft-fail per gotcha #14: missing `Staffing Efficiency` / live `Upkeep X` / live `Workforce <Class>` sheets hide their dropdown / inspect section. The extractor still reads the old dashed upkeep/workforce sheet names as compatibility fallbacks, but missing reports name the live contract (`Upkeep Energy`, `Workforce Engineers`, etc.). The frontend gates each dropdown on `map.available_categories.<category>` and derives grouped metric menu options from the emitted tile keys, so `helium3`/`money` upkeep tabs appear without hardcoding them as yield options. When you add a new metric category, mirror this pattern: register a flag, hide the dropdown when false, render `—` for missing per-tile values.
20. **Workforce sheet names follow `ClassTable`.** `extractors/map.py` reads class names from the `ClassTable` named range (the source of truth `pops.py` also uses), then attempts `Workforce <name>` first and `Workforce - <name>` second. There is no shared `CLASS_NAMES` constant; renaming a class in `ClassTable` flows through to both pages automatically. The frontend's `CLASS_COLORS` palette is independent and falls back to `var(--accent)` for unknown classes — heatmap colour for an unknown class is the resolved amber, not a hard error. Excel's 31-char sheet-name limit means class names ≥ 20 chars can produce truncated legacy sheet names that won't match `read_grid_optional` lookups; the test fixture pre-truncates one dashed legacy sheet to surface this realistically (see `tests/fixtures/build_test_workbook.py`).
21. **`LayerMenu` popup-menu component for grouped tabs.** `src/lib/components/LayerMenu.svelte` is the trigger-button-plus-floating-menu used by Map.svelte for the Yields / Upkeep / Workforce Demand dropdowns. Esc inside the popup `stopPropagation()`s — Map.svelte's page-level Esc handler (clear filters → un-pin) only fires when no popup is open. Outside-click closes via `<svelte:window on:click>`. The trigger label format is `{Label}` when inactive, `{Label} · {Sub-Label}` when this dropdown is the active layer; clicking the trigger when inactive dispatches the last-used sub without opening the popup (1-click toggle). When you add another grouped-options tab, reuse this component — don't reimplement.
22. **Map drawing coords are anchored at `BASE_TILE = 16`; rendered size is decoupled.** `MapCanvas.svelte` fits the full map at 100% by taking the smaller of available content width and available viewport content height, then applies the user-controlled zoom multiplier (`0.75×`–`2×`, default `1×`). The canvas always *draws* at BASE_TILE coordinates and applies `ctx.setTransform(displayScale * dpr, …)` once per draw to handle both scaling and Hi-DPI. The SVG `viewBox` likewise stays in BASE_TILE units, so all literal SVG coords (`width="10"`, `font-size="6"`, `r="2.5"`, etc.) keep working at any rendered size. Two-layer wrapper: `.map-canvas-wrap` measures available column width; `.map-viewport` holds focus + keyboard handlers, has `overflow:auto`, and gets an inline `--map-viewport-width` so the bordered scroll frame hugs the rendered map instead of leaving an empty side band; `.map-content` is sized inline to the rendered pixel dimensions. Border width matters: scale calculations subtract the 4px-left + 4px-right viewport border from available width/height, and `viewportCssW` adds that border back so mobile 100% does not create horizontal scroll. When you change the drawing pipeline, **never reach for the displayed pixel size from drawing code** — write at BASE_TILE coords and let the transform handle the rest. Zoom state lives in `Map.svelte` as a single source of truth, persisted to `localStorage['scorp.map.zoom']` via `src/lib/map-zoom.js` helpers (`clampZoom`/`stepZoom`/`resetZoom`/`readZoom`/`writeZoom` — all wrap localStorage in try/catch and clamp on read); `MapCanvas` is display-only and dispatches `zoomstep` events for the `+`/`-`/`0` keyboard shortcuts. The `.s-zoom` control sits inside `.layer-tabs` and includes the label, `−`/`+` buttons, a range slider, and reset/readout button. **The grid track hosting `<MapCanvas>` MUST use `minmax(0, 1fr)` — bare `1fr` is shorthand for `minmax(auto, 1fr)`, and the `auto` floor lets the column expand to the widest item's min-content. If the measured available width feeds back into content size, that creates a positive feedback loop: content grows → track grows → measured width grows → `fitScale` grows → content grows again. Each ResizeObserver tick multiplies by `zoom`, so a single click of `+` blows the map up by ~22× instead of 1.25× (verified in `tests-e2e/map-zoom.spec.js`'s "scales linearly" regression). Map.svelte uses `lg:grid-cols-[minmax(0,1fr)_300px]` precisely to break this loop. Tailwind's `grid-cols-1` already expands to `repeat(1, minmax(0, 1fr))` so single-column breakpoints are safe by default; arbitrary-value variants are the trap. If you add another grid breakpoint or move `<MapCanvas>` into a different track, keep the `minmax(0, …)` floor.**
23. **Improvement catalog is the canonical category source.** `src/lib/improvement-categories.js:getCategorySlug(name, catalog)` checks the catalog first via `resolveImprovementRow` (exact match → deterministic longest-shared-prefix fuzzy with min-length-4 floor and 75%-of-longer threshold), falls back to the legacy keyword regex (`regexCategorySlug`), then `'other'`. `extractors/catalog.py` accepts the live workbook shape where `ImprovementsCatalog` starts on the first data row and the headers sit one row above it; don't "fix" that back to header-only named ranges unless the live workbook changes. It also aliases live category labels into dashboard slugs: `Food → agri`, `Materials → materials`, `Housing → habitat`, `Faith/Culture/Recreation → civic`, `Research/Economy → science`. Map-canvas redraws are NOT triggered by `mapData` change alone for catalog arrivals — `MapCanvas.svelte` adds a reactive line that re-fires `drawTerrain(...)` when `$catalog` changes, so tiles re-colour when the catalog file lands after `map.json`. Catalog is loaded globally from `App.svelte` (NOT in Map's onMount) so the reactive trigger has a stable subscription window. In the Map inspector, `t.improvement.name` is the workbook's `Improvement Type`; `t.improvement.ownership_type` is the separate ownership classification and is often blank in live data. Don't move the load site or relabel those fields without updating that reasoning.
24. **Predicted Growth / Status Population delta are authoritative, not derived.** Demographics' Predicted Growth reads `totals.total_births - totals.total_deaths` from `demographics.json` — i.e. the GM workbook's `TotalBirths` named range minus `TotalDeathsPerTurn`. Status's Population KPI delta uses the same births-minus-deaths count via `status.demographics.total_births` / `total_deaths`, and the Status Pulse row surfaces `total_births` directly as "Births / year" beside "Deaths / year". Status's Pulse "Projected Growth" rate is also based on those actuals: `(total_births - total_deaths) / population_total * 100`; it must not display `net_delta_pct`, because the estimated rate can contradict the actual births/deaths totals. We did NOT keep the older `pop × (effective_growth × housing_growth_mult − cdr)` or `pop × net_delta_pct` rate-based estimates as fallbacks because the rate-based versions drift noticeably from per-class actuals (rate uses colony-wide satisfaction elasticity; housing mult only multiplies births; rounding only happens once at the end). When `TotalBirths` / `TotalDeathsPerTurn` / population are missing (or population is 0), the count/rate renders `—` rather than silently falling back to the worse number. The `effective_growth_rate` / `net_delta_pct` keys still flow through `extractors/demographics.py` and `extractors/status.py:_demographics_block` for historical/extractor compatibility, but frontend actual-growth displays should not use them.

The `FederationChamber` parliament diagram was dropped from this tab to match the mockup (the component + its test stay for reuse); when `congress.json.federations.delegations` is empty the Federations tab renders nothing and the route shows a "not published yet" card. `partyColor()` (`PARTY_COLORS` mirrors Discord role colours for current parties: ALLB #ff474c, NCC #3a9443, SRF #960202, EDU #003366, LRA #b8893e; Development League #3498db) and `faction-colors.js:federationColor()` (8 live federations pinned to their dominant member-class colours) still back the colour vocabulary. The mockup's Professional/Labour "bloc" tags and "Class Divide" cards were deliberately NOT ported — that taxonomy is not in `congress.json` (the user asked to avoid the hardcoded bits). Enrollment stats, federation stance radars, and federation→party support matrices remain deliberately unsurfaced — see the spec + addendum (`docs/superpowers/specs/2026-06-11-congress-page-design.md`) before adding bands.

57. **The Command page replaces Status at `/` and is timeline-driven (ported from the "Colony Command" design mock).** `src/routes/Command.svelte` (page key `['status','situations','parties']`) hosts two in-page tabs: **Command** (`src/lib/components/command/CommandView.svelte` → Vital Signs, Resource Telemetry, Overton Window, Situation Board) and **Telemetry** (`src/lib/components/telemetry/TelemetryView.svelte` → Trend chart, ring-gauge Instruments, Resource Sparklines, Situation Readout). The old `Status.svelte` / `Status.test.js` / `status.spec.js` are retired; equivalent parity coverage lives in `command/VitalSigns.test.js`, `command/ResourceTelemetry.test.js`, `timeline-frames.test.js`, and `tests-e2e/command.spec.js`. If a merge from `main` resurrects `src/routes/Status.test.js`, keep it deleted and move any still-relevant assertions into Command parity tests; `/#/status` is no longer a route. **Data layer:** the pure `src/lib/timeline-frames.js` builds per-year frames — the **live (latest) year from `status.json`** (richest source; carries births + active situations; this is the byte-identical parity anchor — never build the live year from its own snapshot) and **archive years from `history/year-NNN.json`** (snapshots store no births/situations → those fields are null/empty). `src/lib/stores/timeline.js` exposes `frames` / `currentFrame` / `prevFrame` / `effectiveIdx` / `isLiveYear` / `selectYear` + `loadTimeline` (loads status+history+parties; situations is already global) and persists the year cursor to `localStorage['scorp.command']`. Party stances + `vote_share` come from `parties.json` and are year-independent (shown on every year, matching the mock). The Situation Board + load gauge reuse the **global** `situationLoad` / `crisisBreach` stores and `CrisisGauge` — never a parallel breach calc — and are live-only (archive years render "no situation record"). **Status parity preserved:** Money headline = the Money *resource* `current` shown as the **Treasury** vital, not `treasury.money` (#35); Population delta = births−deaths on the live year else year-over-year (#24); births, **Projected Growth %**, and Housing capacity/util live in the Population drill-down; the Crisis vital reuses the global `.crisis-over-tag` "OVER 1.0" flag when breached (positioned inline via a scoped override). Money + Housing are excluded from the resource list (`RESOURCE_ORDER` in `src/lib/resource-colors.js`) so their magnitude can't dominate the shared bar scale — Money is the Treasury vital, Housing surfaces in the Population drill-down. Shared helpers: `src/lib/command-format.js` (tone→colour, delta arrow/tone, re-exports of `format.js`/`status-metrics.js`); primitives `MiniBar` / `Swatch`; chrome `TimelineBar` (scrub + ▶ play) and `ScanlineOverlay` (toggle; uses the pre-existing `--scanline` token; static stripes so reduced-motion-safe). The history index writer (`scripts/history.py:_update_index`) is now **directory-aware** (unions every on-disk `year-*.json` with the current year) so a stale index self-heals — that's what lets the timeline see all years instead of only the most recent sync.

57. **Social privileges are a 0-10 score, not a percentage.** `pops.json.classes[].social_privileges` comes from the Popsim social-privileges standing scale, so live values such as `5.0` must display as `5/10`. The Census Standing block and ClassDetail Living Standards card should both use this score format; do not send the field through `fmtPct`/`pct`, which would render `500%`. `src/lib/components/ClassDetail.test.js` has a regression for this.
